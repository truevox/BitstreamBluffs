# Ghost-in-a-Link v1 — initial isolated codec (issue #69)

**Status:** draft codec + Game Over export + explicit recipient preview/watch UI; not shipped and no imported playable racer or hosted fallback. Do not close #69. Player account, online API, uploads, official verification, ledger credit and wallet spending are all **outside** this implementation. Separate P0s #119, #244 and #245 own authoritative savestate, protected evidence and public eligibility. The codec cannot replace them.

`src/systems/ghost/GhostLink.js` supplies two explicit-call-only functions:

- `createGhostLink(tape, location.href)`: compresses an allowlisted real SIM9 original Ghost Tape with browser gzip, prefixes a versioned fragment `#bbghost=1.<sha256-prefix>.<base64url>`, strips URL query, source run ID, timestamps and unrelated profile/private fields. Does not fetch, copy or navigate.
- `parseGhostLink(pastedUrl)`: verifies a single bounded versioned fragment, compressed checksum, capped decompression and supported SIM/tape/RNG/state/input/checkpoint/trace. Returns **`trust: 'unverified-local-practice'`** with all credit/official flags false and an isolated `shared:<digest>` ID. It never saves/imports automatically. **The SHA is corruption detection, not producer authentication.**

A URL hash is not transmitted in a normal HTTP request. The draft Game Over **Course Ghosts** modal now has a keyboard/touch accessible **SHARE LINK** action: first activation prepares the link and shows an input/loadout/score disclosure, copying NOTHING; second activation deliberately **COPY LINK** writes it to clipboard. Moving focus away disarms confirmation; concurrent preparation results are discarded if selection changed, and clipboard-denied browsers show a failure instead of silently reporting success. There is no automatic sharing after a crash, save, favorite, or mode change. A link can disclose seed, selected biomes, score, inputs, movement and upgrade choices. Show that before any copy/send. Import must require explicit acceptance and render an unranked practice-only ghost—never authorize wallet claims or an official score.

**Explicit incoming-link preview:** On the Title screen, **ENTER SEED → OPEN GHOST LINK** (or **Shift+Enter** from the seed input, **gamepad X** while the seed modal owns menu input) opens a separate GhostLinkView with its own DOM paste field; there is no new overflowing title menu row. A direct hash URL is hinted and prefilled ONLY on deliberate view opening, **never decoded at page load**. Press PREVIEW (or Ctrl+Enter) to validate untrusted data and render a read-only neon trace. Pointer/gamepad arrows or **Ctrl+Left/Right** while the paste field is focused scrub through recorded 30Hz samples; **Ctrl+Shift+Enter** toggles WATCH; WATCH/PAUSE animates the recorded trace only when the live Reduce Motion setting permits it (otherwise manual scrub remains available), with no physics, RunScene, network call or replay persistence. A second malformed link removes the former preview immediately. Exiting destroys the DOM field, active animation and untrusted candidate. The modal explicitly labels the replay UNVERIFIED and prohibits leaderboard/wallet credit. This is a **visual replay preview**, not a playable race or imported saved favorite.

**Length:** recommended <=1,900 chars; direct browser links accepted up to **8,192 chars**, with a future warning that some messenger/QR apps truncate long URLs. Actual short 141-tick SIM9 tape produced **1,498 characters**; a naturally completed 849-tick run (166m) produced **4,873 characters**. Both round-tripped in real Chromium. A larger replay requires an explicit opted-in hosted fallback with secure untrusted reads; no anonymous upload endpoint or browser-side R2 write token is created.

**Evidence:** `tests/src/ghost-link.test.js` rejects corrupted, malformed, oversize and unsupported versions; guards course, inputs, finite poses, nested fields and zip bombs; prevents auto-network access. `tools/test-real-ghost-link-browser.mjs` exercises actual source tapes from a browser game. This is a source-verified codec **with a draft player-facing export action**, not yet end-to-end sharing/import.

**Outstanding:** a truly playable ghost-racing/practice mode with audited non-rewarding gameplay lifecycle and explicit opt-in; larger replay hosted fallback (>8192 chars), richer compatibility warnings; independent exact-head code/security review and physical-device QA. No production physics, replay schema, PWA, media source or existing save changes.

The real browser acceptance driver additionally opens the *actual* Game Over ghost modal, clicks the genuine SHARE LINK hit zone, verifies **zero** clipboard calls until second confirmation, navigates away and proves that disarms the action, then re-arms and copies once. Both an actual 141-tick controlled crash and a natural 849-tick/166m death complete the flow; the long link gives a truncation warning.

**Compiled real-browser proof:** The acceptance driver creates a real source tape, copies using the actual Game Over button, opens Title → Enter Seed → Open Ghost Link, fills the DOM field without auto-parsing, explicitly previews/scrubs/watches the trace, and rejects a malformed subsequent link while proving saved record/ghost counts are unchanged. A second fresh browser page arriving directly at the copied hash does not start gameplay or decode anything; only pressing Ctrl+Enter after opening the modal creates the read-only preview. Both root and GitHub Pages PR subpath release builds have passed; a natural 849-tick, 166m run has also passed compiled root acceptance. This is an untrusted visual display, not authenticated race evidence.

**Input accessibility acceptance (candidate only):** The seeded textbox keeps ordinary Enter-to-start; Shift+Enter opens the guest-link preview without needing a pointer. From the guest paste field, Ctrl+Enter validates, Ctrl+Left/Right scrubs, and Ctrl+Shift+Enter toggles trace WATCH/PAUSE; the on-screen buttons also work with pointer/touch. In real Chromium the compiled Pages-subpath end-to-end source was tested both desktop-sized and at a 412x915 touch/mobile viewport. This is **emulated mobile Chromium only**, not verified Android hardware/Chromebook acceptance.
