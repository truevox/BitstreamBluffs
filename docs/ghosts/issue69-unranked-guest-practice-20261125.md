# Issue #69 — opt-in UNRANKED guest trace practice (draft acceptance plan)

This is a separately gated follow-up to the shipped v2.22.6 **visual-only** Ghost-in-a-Link. A deliberately previewed, source-decoded SIM9 `normal`-mode guest tape may be selected for a **new locally simulated run** on its exact seed and biome mask. The player steers their OWN sled; the guest's unverified 30Hz pose trace is a visual-only opponent. It must NEVER be mounted as an input-driving `TapePlayer`, a physics body, a score source, an official Daily, a local Favorite or a trusted public result.

The Title preview has a two-action confirmation with explicit `NO XP / SHARDS / SCORES / SAVE` copy. A one-shot in-memory registry handoff starts a new ordinary physics RunScene with the exact seed/mask, clears after launch, and rejects unsupported/malformed modes. This follow-up currently permits only normal-mode current-SIM9 guest traces; Daily/draft and mismatched physics are rejected, not guessed compatible.

RunScene emits a `RUN_START` with `practice:true` so live mission toasts are suppressed, doesn't create/persist a ghost tape, doesn't credit BSOD achievement/Gym unlocks, doesn't write a RunRecord or emit RUN_END. It emits RUN_ABORT on a practice crash, then returns directly to Title rather than showing a stale ranked Game Over ledger. Pause/quit also uses RUN_ABORT. No wallet, upload, network, ranking, profession XP or ledger mutation. The normal non-practice path should be byte-for-byte behaviorally unchanged.

Test gates: pure policy and boundary unit tests; compiled Chromium explicit consent and launch on a real recorded URL with guest displayed and tick advancing, induced fatal crash back to Title; compare SaveStore/ProfileStore/GhostLibrary, records/XP/mission unlocks before and after; direct ordinary run after practice must not retain the guest or practice state; forged guest score must never credit; fallback to normal gameplay and existing GhostLink visual acceptance. UI keyboard/gamepad access and physical Chromebook remain separate gates until verified. **Do not merge without audited non-rewarding end-to-end acceptance.**

## Actual first acceptance (draft, not release approval)

Real headless Chromium root-page end-to-end (own fresh recipient browser context) executed the actual Game Over export -> incoming explicit preview -> RACE GUEST first disclosure / second confirmation -> Title-to-RunScene transition. The player-controlled normal-physics sled and single magenta GUEST trace both advanced; after a real BSOD-catch crash the scene emitted RUN_ABORT and returned directly to Title, with no RUN_END, GhostTape creation, SaveStore run, ghost library write, profile XP/shard/achievement/mission changes or stale Game Over ledger. Exact before/after profile JSON matched, and runs/tapes/courses stayed zero. This is local automated software rendering, not a physical Chromebook.

A second real-browser pass paused a guest practice run, chose RESTART and confirmed the next RunScene remained practice and had no recorder/score credit. Then Pause -> QUIT -> ordinary Title START RUN correctly cleared the guest handoff: normal recorder resumed, no guest trace remained. The source tripwire will require an explicit no-causal-change attestation for the new conditional unranked branch; this does NOT certify cross-engine replay parity. The guest pose is visual-only and players use **their own profile loadout**, so there is no claim of equal equipment/boosts or of a trusted race winner.
