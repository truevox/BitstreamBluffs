# Music Friday — More convincing vinyl and four-beat crash comeback

**Design research, November 19, 2026. No game code, samples, score catalog, or deployment altered.**

## What Marvin has already decided, versus what remains open

Marvin approved **fatal crash → short vinyl scratch → 1–3 beats' silence → four beats of drums → original full band**, with the soundtrack's transport still moving and instant retry never held up. The existing effect is merged and released. On actual listening Marvin said **the comeback sounds great**, but the four identical sampled drum hits sound *somewhat looped* and the noise/triangle-tone scratches do *not* sound like real record scratching. He suggested, as alternatives rather than a final choice, **the original drum stem**, **a newly recorded MIDI drum performance** (not extracting MIDI from the original), and **several different original source drum hits**. Marvin then approved **auditioning all three**. Their short playable A/B/C previews and editable MIDI are published separately at `docs/music-review/drum-countin-ab-20261119/` on this feature branch. No winner has been chosen.

## The root cause of today's scratch timbre

`src/systems/music/TurntableScratch.js` currently generates a 205 ms filtered-noise sweep, playback-rate envelope and separate triangle oscillator. It has **no recorded musical PCM moving backwards or forwards**. Spectral movement is not enough: a convincing turntable scratch generally needs audible music transients sliding in pitch/time, non-linear hand motion and abrupt crossfader cuts. Passing existing scratch duration, direction, mute and cancel tests does **not** show that it sounds like a physical record. The current manual Pause/Resume implementation must remain separately tokenized and exact-frame-resumable; fatal scratch must never introduce a second playlist player or restart the song.

### Proposed design S1: platter scrub of the already licensed song

- **Precompute on track readiness, not during crash:** take a bounded stereo snippet, e.g. 160–350 ms of rhythmically identifiable guitar/chiptune/drum mixture around a suitable onset from the *already decoded current OGG* source. Record the source segment/frames and SHA-256; don't encode or duplicate full music masters. Generate a small reversed view/copy of that snippet using existing PCM samples so backward playback is reliable across browsers. No network SFX dependency. This is a **scratch effect one-shot**, not a second song transport.
- **Define a physically motivated gesture, not an abstract oscillator sweep.** An initial plausible 205 ms stop-scratch envelope: rapid short forward drag, brief backward pull, then a decelerating forward stop; resume is a compatible forward re-acceleration. Piecewise playback position is integrated from a continuously varying signed velocity with a *short stationary hand pause* and intentional crossfader gaps. Stereo phase and sample continuity are checked at reversals. The absolute song transport never seeks or stops except when the existing manual pause contract expressly freezes it.
- **Audio implementation options:** pre-render a tiny ~205 ms PCM gesture from this snippet for deterministic replay, using band-limited interpolation and fades; OR use several independently scheduled tiny forward/reversed buffer slices on the existing music bus. Do **not** rely on setting negative `AudioBufferSourceNode.playbackRate` at runtime as an untested universal backwards-playback primitive. Pre-rendering tiny buffers is the simpler reproducible research candidate.
- **Crossfader:** 3–8 ms fades at each reversal/cut, a little carefully filtered surface texture, no exposed click/pop, no automatic reverb tail that masks the beat silence. Preserve exact scratch-to-silence handoff. Keep speed and transients audible but avoid over-bright or excessively loud sweeps. Use existing music and master gain controls; muted soundtrack means muted scratch.
- **Available fallback:** if valid current-track samples are absent, maintain existing short synthetic scratch or no scratch, never block a fatal crash, Game Over, initial menu, immediate retry, or manual pause. Ignore stale-generation scratch nodes on track/jukebox/transport changes. No sampler/timbre cache should survive track replacement incorrectly.
- **Optional comparison S2:** a genuinely recorded turntable scratch with clearly verified public-domain/CC0 or licensed provenance (not merely 'free download'). Only adopt it after confirming license and testing whether its sonic character suits the actual music. No external SFX has been obtained or selected yet.

**Reference A/B test (not yet rendered):** S0 existing 205 ms noise/triangle, S1 resampled original-song scrub, and S2 licensed real vinyl scratch *if appropriate*. Keep same original underlying song, same duration, same loudness target and effect route. Test pause and resume separately; a satisfying crash scratch should not force identical gestures on user-initiated Pause and Resume.

## Drum count-in: design to retain source authenticity and four clear beats

Current `FatalCrashCountIn.findOriginalDrumAccent()` chooses one audible ~140 ms source hit then plays **that identical PCM clip four times**. This mechanically guarantees four audible beats at unverified 0.5s spacing, but explains the audible repetition Marvin noticed. The current game has a distinct `recovery` gain on every source in `MusicFXGraph`, which can temporarily route a natural original drum stem while gating other stems. That source gate works without altering adaptive/orchestra motion gains or the original song transport. Existing MIDI demo is an editable SMF0 with a new original synthetic kit; it is **not** transcription or an acoustic performance.

**Next candidate D — original-drum-anchored adaptive hybrid (recommendation, not approval):**

1. Identify the actual recording's quarter-note phase before switching from synthetic research timing. The original *One More Run* Suno style prompt specifies **160 BPM** and deliberately includes a **half-time bridge**. A strict 375 ms clock is a **test configuration**, not the approved song's true quarter-note frame grid, and cannot be inserted into `RELEASE_BEAT_GRIDS` without verification.
2. When fatal crash occurs, keep original `StemMusicDirector` clock and all source nodes moving. Gate instruments/voice away. At the start of the four-count, allow the original **`drums` source input** at normal user mix gain to pass while all other sources remain gated, *if* that passage contains suitably clear original strikes. If a true natural rest/fill leaves a weak beat, layer one **different** source-derived hit on that scheduled slot; don't mindlessly fire all four extra accents over already audible natural hits.
3. Define **four musical count slots**, not merely four sampled source nodes. For each count slot the algorithm must guarantee a perceivable accent if the user requires exactly four, but natural hi-hat/ghosts should not be mistaken for primary kick/snare beats. Use short attack windows and minimum-perceived-level safeguards. On active source hits, use zero or subtle reinforcement, avoiding obvious flams. In a breakdown or drumless intro, switch to arranged varied original excerpts or a previously approved MIDI-rendered drum kit.
4. At the next phase-verified downbeat **after four count pulses**, restore all original music channels with a short click-free ramp. Preserve the source song's position and all prior mute/jukebox choices. A new immediate run does not reset this plan. Manual Pause, explicit jukebox selection, soundtrack mute/disable and ordinary quit retain their existing authority.
5. If beat grid is **not** verified for a particular track/section, keep using the **current synthetic, explicitly unverified and gameplay-safe behavior**. Do not claim an unverified inferred beat is source truth or block rider physics. No extra stem decoders/player, repeated Git assets, new full OGG copy, or memory-unsafe late buffering.

### Engineering validation required before choosing/integrating a sound

- **Musical listening**: A natural original drums, B recorded-MIDI drum kit, C four distinct original hit slices; possibly D hybrid. Audition all four songs, multiple source sections including drumless intros, fills, transitions and the *One More Run* half-time bridge. Distinguish 'sounds musically intentional' from mere 'four hits audible'.
- **Sound/quality**: match LUFS or short-window RMS for *comparison* (never independently master the different versions into incomparable mixes); check peaks/headroom, clicks at source cuts, choppy reverse sound, phase continuity, and 205ms silence boundaries. Human chooses feel before shipping.
- **Safety**: real fatal BSOD vs shield save and Gym catch; crash sound unaffected by RunEnd, four count slots survive immediate retry/new run ID; no frozen song clock; optional audio/codec failures cannot trap Game Over. Correct behavior for both a source rest and four naturally audible drums. Unit tests and real four-track Chromium WebAudio waveform and gameplay tests. Music mute, reduced volume, and user jukebox intent override every one-shot and envelope.
- **Documentation/provenance**: mark source SHA + chosen excerpt offsets, extracted/recorded MIDI provenance, intended 160 BPM vs measured pulse, human listening approval, and original-vs-hybrid choice. Log synthetic research grids as synthetic, never silently promote them to source-approved beat catalogs.

**Release gates remain separate:** this is *design only*. Original vocal performance and sampled original songs stay unmodified. No need to change World Dance or its visual-only energy reaction to music during these sound experiments.
