# Optional piano-friendly *One More Run* melody — first source-grounded listening prototype

**Music Friday · November 19, 2026 · [Issue #37](https://github.com/truevox/BitstreamBluffs/issues/37) · feature branch `feature/music-piano-friendly-melody-20261119`.**

**What this is:** A first, playable **machine-generated, unverified** arrangement of Maxi M.'s sung melody, against *the actual song's original instrument stems*. This is deliberately **an audition, not a replacement** for her finished music. Nothing modifies original vocals, immutable music packs, performance scores, beat grids, saved user settings, or ordinary game audio. It is not a verified or human-corrected music transcription.

## How to listen

From **Settings → Manage Sound → Music Lab → PIANO**, a separate music-review page opens in another browser tab. The isolated Lab music director pauses before opening it. No preview autoplays; choose a passage and listen to its three alternatives. Switching A/B/C **within that passage** jumps to approximately the same playhead time to isolate the melody changes. The preview page is also directly available at `/music-review/piano-friendly/index.html` after Vite/Netlify serves the feature branch. The actual game source soundtrack and user profile are untouched. The player uses the browser's own audio controls, not an in-game persistent music setting; the game does not change volume, mute, gameplay timing or unlock state.

Four 24-second source windows **0:24–0:48, 1:00–1:24, 1:48–2:12, 2:24–2:48**, each with three original-accompaniment context variants:

- **A — Original recorded Maxi vocals:** exact recorded original vocal OGG in this passage over the original drums/bass/guitar/piano/other OGG.
- **B — Piano-friendly simplified melody:** source vocals analyzed by original-OGG YIN/voicedness, stable pitch centers rounded to semitones, tiny vibrato and unmusical note-tail bends removed, represented by a soft **synthetic piano-style instrument**. This can sound stiffer than Maxi's original; that's intentional as a comparison. No verified beat phase exists, so preserve the original detected note onset/offsets rather than forcing grid snap.
- **C — Selectively expressive piano-style melody:** same synthesized instrument and original accompaniment, but the classifier tries to preserve *large coherent onset glides* by rendering short discrete piano stepping notes on the way to the intended held pitch. This is not physical pitch-bending on a piano.

The B/C full-song research scores are also exported as **editable standard MIDI files** (160 BPM tempo from the owner's Suno prompt to encode source-time seconds; this is **not** proof of a verified beat grid). Each note's extracted start, stop, intended pitch, bend label, and input-source 15-segment hash are in `unverified-source-contour.json`; `manifest.json` contains original pack SHA and per-MP3 content hashes. 12 MP3 preview files and the offline self-contained playback HTML are under `public/music-review/piano-friendly/` (Vite serves this at `/music-review/piano-friendly/`). The single offline reconstruction script is `tools/music/render_piano_friendly_melody.py` and can regenerate outputs from a full, licensed OGG pack with cached ffmpeg, librosa, NumPy and SciPy. None of the original source WAV/OGG files are stored again in this feature branch.

## Known limitations / honest interpretation

- The existing `bitstream-performance-v1` schema has only integer note pitches, **not vocal pitch-bend curves**. We extracted the *source vocals themselves*, using librosa YIN pitch at **16kHz/10ms hop**, amplitude RMS and spectral-flatness gating, median filtering, phrase segmentation, and separate stable/structural-glide/terminal-ornament classification. Do not treat this as human-truth piano sheet music. Whispered/screamed/noisy notes, double-tracked vocals, short ornament notes and octave errors can fool a monophonic detector.
- The Suno Style Prompt asks for **160 BPM with a half-time bridge**, but the output recording's beats and phase are **not yet verified**. Timing quantization cannot meaningfully move notes toward an untrusted grid. This initial 'piano-friendly quantized' version therefore **quantizes pitch/ornaments, not song timing**. This is a deliberate fail-safe; actual slight timing quantization remains a later human-reviewed refinement.
- **Passage 2 (1:00–1:24) contains no confidently detected large onset glide.** Its B and C MP3s are identical by design, so this section mainly tests the simplified note interpretation. The page clearly labels that fact.
- The candidate uses a **deliberately synthetic struck-string timbre**, not a sampled Steinway, and its envelopes are simpler than a real pianist's finger/hammer/decay interaction. Repeated phrases with same source pitch can legitimately retrigger. A 'selective expressive' track may be very similar to the simplified track except at candidate strong glides; that is expected.
- Each 24-second passage includes **the original instrument stems and only one voice**, not original lead vocals plus piano together. No singing is replaced in the game's active tracks. Review clip loudness shares common gain within each A/B/C passage, rather than mastering away natural relative differences.
- 4×24 seconds are sampled from the original 174.6s recording for human review. The MIDI/contour analysis spans the full track but a full-length published piano playback track is not claimed.
- Provisional generator counts are candidates, not validated notes; to build trusted note mappings, obtain human markups on meaningful slides, little terminal scoops, unreliable screams and timing against the source recording.

## Acceptance / release policy

Python note-classifier tests include steady note, dramatic rising scream glide, terminal-scoop removal, vibrato, two same-note attacks separated by a rest, unvoiced area, octave spike, source onset preservation, MIDI events and original score immutability. Browser/HTTP/MP3 source assets should be verified before PR review. The current Music Lab button opens an external same-origin listening tab; the page's audio does not share WebAudio user mixer, so **the review page should never auto-play**, and all audio stops on pagehide. Closing the game Lab stops its sandbox and restores normal game music bus as before. The PR should remain **unmerged until owner audition/approval**. In particular, don't infer approval of these note timings, piano timbre, or future replacement from an automated test pass.
