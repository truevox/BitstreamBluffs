# #424 stock base-run Suspend and Resume — player-facing pre-alpha

## Contract

Players may explicitly select **SUSPEND RUN** from the Pause menu, then select it a second time to confirm **save and quit**. This is NOT an automatic checkpoint or rewind. A failure keeps the paused gameplay intact, displays a status warning and never silently overwrites or deletes an existing save. Once saved, the original scene quits without awarding a run.

A compact **R RESUME** Title chip (also keyboard `R`) is disabled until an *inspection-only* `LocalSuspendSlot.peek` confirms a ready, exact-build, exact-layout local envelope. The button and failure status are client-side only; no server, telemetry transfer, leaderboard grant or other data export is required. The resume action atomically claims the one-use slot in the same IDB transaction, excludes concurrent other tabs, and reconstructs a fresh hidden, non-ticking RunScene using all eight canonical signed native sections. Nothing is rendered or allowed to score until full native state/recorder restore and **slot consume** succeed. A failed restore disposes the scene first and releases a still-held token only after safe disposal; otherwise it leaves a loud locked warning rather than risking duplicate claims.

This first release intentionally refuses non-base biomes, replay/ghost-takeovers, Gym, official daily, modded or upgraded runs, Kodiaks, magnets and active boosts. It is bound to the current exact build and DOES NOT migrate old saves across automatic PWA updates. Corrupt, mismatched-version and claimed slots are **retained**, not silently deleted. This does not establish trusted remote verifiers, official Verified status or public Shard credit. Existing ranked scoring rules are not broadened.

### Minified production class identity

Production esbuild renames JavaScript class constructor names. The original native graph snapshot kept `constructor.name` for `Hazard`, `PowerUp`, `Sled` and `ShardField`, while the strict typed entity-state section requires those four stable names. In a real bundled mobile browser, saving failed closed at `entity-state:hazards/0/0/class` and then `entity-state:shardField/class`. Each of these four local entity classes now declares a stable static `NATIVE_SNAPSHOT_CLASS` literal on its constructor. The runtime serializer checks the tagged constructor prototype (not an instance field), so mock-Phaser unit tests do not eagerly import the actual Phaser gameplay classes. The untrusted serialized class tags remain validated exactly and cannot select a JavaScript constructor. Existing source diagnostic tooling remains unchanged. Production compiled Chromium now passes the actual Pause touch ×2, page reopen, Title touch and exact non-ticking reconstruction, including a read-only IndexedDB empty-slot check. The dedicated CI gate runs this compiled test **in addition** to source/development-browser deterministic suffix tests. Any future class-name drift must make this production gate red.
