# #244 — Real Chromium IndexedDB quota refusal and recovery (2026-11-25)

**Reproducible test:** `GAME_URL=http://127.0.0.1:PORT/ node tools/replay/test-real-evidence-quota-browser.mjs`, with an isolated, exact-source Vite server and `/usr/bin/chromium` (override `CHROMIUM_EXECUTABLE` where needed). The browser profile/context is temporary and never shares user site data. The test uses CDP `Storage.overrideQuotaForOrigin`, not a fake IndexedDB or mocked `QuotaExceededError`; `Storage.getUsageAndQuota` confirms `overrideActive=true`, `quota=300000` bytes. **Apply the override before the evidence DB is first created.** On this Chromium build, lowering a quota after an open database was established did NOT reliably reject even an oversized subsequent write; the harness rejects that false green by asserting a real quota error.

Two independently hash-checked source tapes come from the existing 46 historical recorded fixtures. The **first** remains a real historical recording converted to a valid legacy full canonical envelope (**2,867 bytes**). The **second is deliberately synthetic pressure data**: `quotaStressTape.mjs` borrows one historical tape's initial structural fields, generates exactly **120,000 deterministic input rows**, and forms a valid canonical *legacy-derived structural test envelope* of **1,702,810 bytes**. This second envelope was **not actually played, recorded, scored, or validated as an honest replay**. It must never be submitted or ranked. The helper is test-only and does not affect live capture, inputs, physics, save files or game distribution behavior.

Real headless Chromium result on a fresh test origin: the small authentic envelope persisted first; under the preconfigured 300 KB quota, saving the synthetic envelope threw a real archive `quota-exceeded` error, left its digest **not durable**, retained the exact canonical bytes in session-only pending memory for export, and did not damage the small persisted envelope. Removing the CDP override and explicitly calling `retryPending({digest})` recovered exactly one pending envelope. Both envelopes were durable, unbound and structurally readable. After closing the original page and loading a fresh page, their persisted bytes matched the expected SHA-256 digests. **No mutating HTTP requests and zero page errors** were observed in the test context. The quota override was removed in a finally block even on failure.

**Limits:** This is a genuine browser **quota-error and recovery-path** test using a *synthetic oversized canonical envelope* to make the error deterministic. It does not establish typical live SIM9 bundle sizes (the historical 46-record corpus is separately measured in `evidence-corpus-244-20261125.md`), actual ChromeOS hardware/storage-pressure behavior, cross-tab quota eviction, persistent-storage permission outcomes, service-worker quota use, emergency large real recording export from a crashing tab, or public replay authenticity/entitlement. `navigator.storage.estimate()` may report the browser's normal origin quota despite the active DevTools override, which is why the test checks CDP `Storage.getUsageAndQuota` instead. The v3 tombstone/deletion fence and source-approved local reference integrity are independent gates.

### Independent review hardening (2026-11-25)

The first independent source review identified two false-positive possibilities in the browser acceptance: `inspectBundle(digest)` reports `runBound:false` without a supplied run ID even if the persisted record was erroneously run-bound; and an explicit quota recovery could successfully write durable bytes yet leave stale session-only pending bytes/metadata queued. The test now inspects the **persisted index through a fresh IndexedDB store** and, after closing the page, verifies both archive-only entries retain an actual `runId:null`; it also asserts `retryPending()` returns precisely `{attempted:1,recovered:1,remaining:0}` and both `pending` and `pendingMeta` no longer hold the recovered digest. Repeated **real CDP quota** Chromium test passed with both new assertions, no page errors and no mutating network requests. These assertions are archive lifecycle hygiene, NOT authentication or a genuine recorded long-session quota threshold.
