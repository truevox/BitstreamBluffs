The publication manifest from #330 is trusted build evidence (14,637 objects, 1,399,907,225 bytes). `planPublishedMusic` validates its format, release identity, unique bounded relative keys, total size, and the SHA-256 and size of actual catalog and supplied pack bytes. It reuses the selection/biome planner and projects every required/bonus original logical path to the exact versioned R2 URL with its published byte length and SHA-256. Missing referenced assets fail closed. This manifest is not a signature; provenance must be maintained by the release pipeline, not taken from an arbitrary client or remote response. ## Candidate mono tier pipeline

`build-r2-mono-pilot.mjs VERIFIED_PUBLICATION NEW_OUTPUT_DIR [TRACK_ID]` extracts only the chosen song's required original assets into an isolated temporary stage, verifies every source byte count and SHA-256 against #330, then uses the existing non-overwriting mono encoder for candidate Lite and Full. Independently decodes each original and each derivative to count 48 kHz PCM frames and refuses mismatches; manifests record original release URL, source/derivative hash, size and exact frame count. Originals are read only; derivatives are local candidate assets, not uploaded. The current bitrate presets are candidates from the earlier audition, not a new listening approval.

`planR2Tiers` binds candidate derivatives to the exact original publication, rejects absent/mismatched stems, and emits explicit **unpublished** physical object keys with logical original URLs. High orders all required Lite before required Full, then optional lookahead; Space Saver only Lite; No Music no groups or media transfers. This is build-time planning, not runtime tier routing or UI. The current original R2 worker does not serve these derivative keys. No media publication, automatic download, or overwrite of stereo masters is authorized by these tools. 42 focused PWA tests pass.

**Real mono pilot PASS:** One More Run's 120 original audio files (10,480,955 bytes) generated 120 Lite (4,094,673 bytes) and 120 Full (8,447,643 bytes), all 240 with identical original decoded PCM frame counts. The actual source-bound candidate tier planner accepted both manifests: Space Saver 4,161,455 bytes including pack metadata; High 12,675,880 bytes for both tiers (shared metadata counted twice in group inventory); No Music zero. Catalog is extra 6,639 bytes. No derivative publication, listening approval or live quality-switch proof is implied. `selectR2Tier` adds conservative stopped-transport promotion/demotion policy, refuses missing group readiness and immediately disables No Music. Runtime callers must verify cache readiness and actually stop/invalidate decoded transport buffers before switching; policy alone is not a transport integration.

**Actual candidate tier browser proof PASS:** `BSB_PUBLICATION_ROOT=... BSB_MONO_PILOT=... node tools/pwa/test-r2-mono-offline-browser.mjs`. Explicit opt-in local candidate router (default worker excludes it) stages 120 Lite and 120 Full verified Oggs from local isolated preview, plus actual R2 release catalog and metadata. Cold offline Chromium retains 33 songs and real game engine plays One More Run with seven mono buffers and no procedural timer in Lite, Full and Lite again. Exact bass SHA-256 differs by tier and matches each manifest. Refuses an attempted non-stopped promotion; actual `AudioSynth.stopMusic()` clears decoded buffers and active source nodes before deliberate switches. No Music blocks recording requests and persists after cold offline reload (503). Zero page errors. No uploads, no production settings/controller integration, no multi-tab or seamless within-song switching guarantee; the candidate worker accepts a caller-asserted stop flag and is solely a developer proof. 46/46 PWA unit tests. Original stereo masters untouched.

## Download control foundation

`R2DownloadControls` coordinates the published original-quality plan (not the unpublished mono tiers). Construction, readiness inspection and rejected consent make no network transfers. Explicit consent, browser quota estimate with a conservative reserve, cancellation, single in-flight queue, byte progress, and hash-based readiness are separate from the UI. Verified cached entries resume; a fully ready queue returns without transfers or quota-estimate dependency. No selected songs means no transfers. Optional lookahead is explicit and after required groups. This is a controller API, not yet player-facing settings or automatic production worker registration. The actual R2 Chromium smoke exercises this controller with navigator.storage.estimate; unit tests also cover denial, insufficient storage, abort and duplicate start. 51/51 focused tests pass.

## Whole-catalog candidate generation

The verified original publication contains 14,591 Ogg recordings across 33 song packs (1,380,899,809 original audio bytes). `build-r2-mono-catalog.mjs` runs bounded per-song workers over every published recording, including alternate biome arrangements, not just menu-required tracks. It binds its output directory to the exact publication inventory SHA-256 and re-verifies completed songs' source hashes, derivative hashes, frame counts and counts before accepting them on restart. Partial/failed song directories are preserved, not silently overwritten. This starts local generation of 29,182 candidate encodes; it does not upload or change the original catalog, claim listening approval, or imply all assets are required for an individual player's download. Initial worker count is two to limit contention on CT223. Actual completeness requires the final batch summary and verified manifests for all 33 tracks.
