# Bitstream Bluffs — continuous soundtrack, first track and persistent shuffle

**User-approved behavior (Marvin, November 18, 2026).** Music should start as soon as the game loads, always choosing **One More Run** for the *first track of a new page-load session*, subject to a track's explicit OFF setting. Thereafter, one continuous soundtrack carries through Title, runs, crashes, Game Over, and back to menus **without seeking, restarting, skipping or switching tracks on transitions**. A song advances only when it reaches its natural end or the user manually presses Next/Previous.

In non-run scenes the **same original song** continues with ordinary, un-biomed accompaniment plus the separately rendered **Debutmont melody voice**, and **no speed/jump/BSOD musical processing**. In a run the existing full biome, speed, airborne, combo and authoritative BSOD wind/danger signals remain available. The menu is not a separate player or independent timer.

**Owner-approved option:** Settings → Manage Sound → **SHUFFLE SONGS** ON/OFF persists between sessions via SaveStore's strict boolean `musicShuffle` (defaults OFF). With ON the initial fresh-load song is still One More Run; after that, each round of enabled songs is shuffled without repeating the current track where alternatives exist. Existing song ON/OFF switches and no-music-if-all-off semantics prevail; environmental wind and UI SFX remain independent.

## Implementation / ownership

- `AudioSynth` / `StemMusicDirector`: keep a single shared decoded-stem player and WebAudio clock. `RUN_START`, `RUN_END`, `RUN_ABORT`, `GAME_PAUSE`, `GAME_RESUME` switch only the DSP presentation. The current song and its timestamp survive. Crash music does not stop or restart. When a song naturally finishes, the existing director pump selects the next enabled track in sequence or the prepared shuffle round. Run-only effects are ignored while in menus, without blocking crash/UI SFX.
- TitleScene calls `AudioSynth.startMenuMusic()` on entry. If browser autoplay restrictions suspend the AudioContext, playback is requested immediately and starts on the earliest actual user gesture using the existing gesture listeners. **There is no browser autoplay-policy bypass**; silent initial load in a restrictive browser is expected until interaction.
- Fresh catalog load chooses `FIRST_SONG_ID = local-one-more-run-bitstream-bluffs`, regardless of playlist/catalog order; explicit disabled songs are respected.
- Menu accompaniment uses the original backing stems without biome FX and the actual pre-rendered `voice:debutmont` melody from the same pack, with normal vocals entitlement unchanged. Active run restores normal biome mixing.
- `SaveStore` sanitizes and persists `musicShuffle`; `SoundManagerView` exposes a persistent ON/OFF control. Jukebox history, previous/next, manual pause/resume and all-off music continue using the same transport. No source scores, Ogg assets, transcription, or note inspector were altered.
- Changes derive from Control Friday's established `BSOD_STATE_CHANGED` audio integration `e97189a`. The controls and music must be integrated as a single compatible feature set; do not transplant into an old branch lacking wind event/settings support.
