# #176 — Friday exact-HEAD review-queue lifecycle

## Why this patch exists

The existing #153/#154 workflow only listened to PR lifecycle events and only recognized `<!-- friday-issue: N -->`. Morgan's #174 had `Refs #79` and a clear `[GAL FRIDAY REVIEW REQUEST]` comment, but no `friday:in-review` label. The review was overlooked. The canonical source of this workflow is also shipped as a companion template by the private `truevox/skills` `friday-github-lifecycle` skill; keep both copies synchronized when updating the template.

## Installed model

- A **read-only** `.github/workflows/friday-pr-lifecycle-signal.yml` receives `pull_request`, `issue_comment` and `pull_request_review` events. It enforces the original **starter-removal PR-head CI gate** using the read-only Git Trees API (inspecting the full head tree, not just changed files), then writes only a tiny validated numeric PR pointer, source event and source comment/review ID artifact. It has no checkout and no permission to modify issues. The **privileged default-branch-controlled** `.github/workflows/friday-pr-lifecycle.yml` handles its `workflow_run` completion plus manual `workflow_dispatch`. It checks artifact count/size and matches source event to the actual triggering workflow run. A pull-request-origin pointer must identify a PR associated with that exact run. For comments/reviews, it fetches the source by ID and validates its target PR, full current HEAD, correct review signal, trusted author association and actual repository write permission. Only then does it run its default-branch helper.
- The trusted privileged `workflow_run` workflow definition exists on the **default branch only**, and checks out **only that branch**, not PR code. The input collector may run on a nondefault PR base but has no issue-write permission; it never checks out or executes PR head code. The writer never runs the collector artifact as code. It uses built-in `GITHUB_TOKEN` (`contents:read`, `issues:write`, `pull-requests:write`), does not merge, and executes `.github/scripts/friday-pr-lifecycle.cjs` only after that script has landed on the default branch. During the patch's own PR, the script is not installed yet, so the Action reports its pending status and does not load the untrusted PR copy.
- A linked issue is recognized through an unambiguous `<!-- friday-issue: N -->` marker, a top-level `Refs/Fixes/Closes #N`, or a `[ #N ]`-style bracketed issue number (without the spaces) in the PR title. Fenced code, multiline backtick code spans, indented code, HTML comments and `<pre>` examples are excluded without joining text around excluded nodes (which could otherwise fabricate `Closes #N`). Conflicting/ambiguous references are skipped; the linked item must actually be a GitHub **issue**, not another PR.
- A **trusted write-capable repository member's** `[GAL FRIDAY REVIEW REQUEST]` comment with **exact, current 40-character HEAD** and a ready/non-starter PR moves both the PR and parent issue to `friday:in-review`. A changed HEAD invalidates the old request; moving a PR back to draft also clears it. A starter marker with `status: removed` is not considered present in the final PR.
- A matching `[GAL FRIDAY REVIEW PASSED]`, `CHANGES REQUESTED`, native GitHub `APPROVED` or native `CHANGES_REQUESTED` verdict leaves/reverts both to `friday:in-progress`. The current verdict is computed from authenticated comments plus reviews on the current HEAD. In particular, GitHub won't allow the PR-owning `truevox` identity to submit a native `APPROVE`: Gal Friday's tool posts a `COMMENTED` review with `[GAL FRIDAY REVIEW PASSED]`, which is **only a label bookkeeping verdict**; it does **not** bypass GitHub's independent-review branch protection.
- A read-only parent-routing job serializes label writes **per linked issue**, not per PR, and preserves pending handoffs with `queue: max`. The pointer artifact is strictly validated as a number plus an allowed source-event name; its untrusted contents never become shell commands or JS source. It re-reads current sibling PRs and current issue labels immediately before the parent transition. Shared parent issues (e.g. #172's two draft PWA PRs) stay `friday:in-review` if **any** linked open PR is genuinely awaiting review; otherwise they remain in progress while an open PR exists.
- After merging a PR: the PR itself becomes `friday:done`. The Action does **not** close or reopen issues; it only updates status labels. GitHub's own default-branch closing keywords can do so for an explicitly full-scope `Closes/Fixes/Resolves #N`; do not use those keywords in partial PRs. A partial `Refs #N` PR does **not** close the issue; stacked merges into feature branches also do not close it. Closed issues can be labeled `friday:done`, but intentional reopening is always respected. GitHub's own keyword auto-closure still applies, so partial-scope PRs must **not** include a `Closes #N` keyword.
- The earlier changed-file and declared-scope overlap advisory remains available on Friday-marked PR lifecycle events, without executing PR code.

## Handoff for agents

1. Claim an issue and open an isolated draft PR (no review label while draft).
2. Finish tests and remove any `.friday/issue-N-start.md` marker; push your final HEAD and mark ready.
3. Post exactly one clear `[GAL FRIDAY REVIEW REQUEST]` comment with the **full current HEAD SHA** and the verification summary. The GitHub Action labels both PR and issue; no agent-side hooks are required.
4. Gal Friday reviews the exact HEAD and submits `[GAL FRIDAY REVIEW PASSED]` or feedback. The Action clears the review label; a new commit requires a new handoff. Separate native required approvals continue to be enforced normally.
5. Merge through the approved orchestrator; keep a partial parent issue open. No automatic merge is performed by this workflow.

For earlier missed handoffs after the workflow is merged, use **Actions → Friday PR lifecycle → Run workflow**, set `pr_number` to the relevant PR. This recalculates only from real GitHub state; it does not manufacture any approval.

## Security remediation staged after independent audit (2026-11-23)

The independent Deep Think adversarial review of #177 SHA `abc6f8ad` found five concrete security issues. This stacked branch addresses them **without activating** the privileged writer:

1. **Untrusted ZIP extraction (HIGH):** The privileged router no longer invokes `actions/download-artifact` or extracts untrusted files into its workspace. It fetches a single compressed archive and validates exact ZIP entry count and path, local/central header agreement, streaming data-descriptor CRC/size, bounded archive/compressed/uncompressed byte counts, strict UTF-8, CRC32, and only a validated JSON pointer. Raw DEFLATE uses `maxOutputLength`. It fails closed on unknown ZIP layouts, oversized content and unknown binary response types. The event pointer has no executable code, and is read from a bounded step output, not filesystem.
2. **HEAD race:** Before PR label writes and on each label operation, re-fetch the real PR to verify exact HEAD, draft status, parent issue, same-repo source and PR lifecycle state. Abort if changed. GitHub has no label CAS, so a push precisely after the final check remains a platform-level race; reconciliation on subsequent events must handle it.
3. **Sibling reparenting:** Revalidate each sibling on every PR write, and re-read final sibling membership/HEADs before parent labels. Abort instead of applying a stale parent decision.
4. **Untrusted comment amplification:** Filter public PR issue-comments by trusted author association and leading Friday review marker **before** allocating the unprivileged collector job. The privileged resolver independently revalidates actual repository write permission, source record and current full 40-hex SHA.
5. **Raw HTML parsing:** Unclosed `<pre>`, `<code>`, `<script>`, `<style>` and `<textarea>` blocks consume the remaining text; fake `Refs`/`Closes` examples inside them cannot route or close parent issues.

Adversarial negative tests cover compressed ZIP bombs, misleading size metadata, path traversal, invalid descriptors, malicious pointer shapes, HEAD-push and sibling-parent changes during reconciliation, late arriving siblings, and unclosed HTML directives. The new security boundary is **draft only** until an independent exact-head reviewer and live GitHub Action event test prove the trusted-main publisher works. No workflow is merged or enabled by this branch; the `truevox/skills` canonical template must be synced and reviewed separately before installation.
